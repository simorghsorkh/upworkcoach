# Rubric بررسی پروفایل (Profile Review) — نسخه‌ی سبک

> upwork-domain-expert — فاز ۱ — ۲۷ مهر ۱۴۰۵ — v0.1 (کوتاه؛ اولویت P1)
> قراردادهای مشترک در `README.md` همین پوشه آمده است. هنوز مجموعه‌ی ارزیابی ندارد و بعد از دریافت پروفایل‌های واقعی هنرجوها ساخته می‌شود.

## ۱. هدف و تغییر مهم ۲۰۲۶
هدف این است که هنرجو بفهمد چرا پروفایلش بازدید یا Invite نمی‌آورد و ۳ اصلاح مهم کدام‌اند.

**تغییر مهم:** طبق صفحه‌ی راهنمای آپورک، **Specialized Profiles از ۲۸ مه ۲۰۲۶ حذف شده‌اند**. پروفایل اصلی حالا «پویا» است و آپورک برای هر کارفرما بخش‌های مرتبط را نشان می‌دهد ([Upwork Help 115013750068](https://support.upwork.com/hc/en-us/articles/115013750068)، از متن نتیجه‌ی جستجو، اکتبر ۲۰۲۶؛ صفحه 403 داد). طبق منابع ثالث، تیتر و Overview پروفایل‌های تخصصی منتقل نشده‌اند ([GigRadar 009](https://gigradar.io/newsletter/issue-009)).
**نتیجه برای rubric:** به‌جای «Specialized Profiles»، معیار «تمرکز و انسجام نیچ در یک پروفایل» آمده است. اگر هنرجو هنوز از پروفایل تخصصی حرف می‌زند، ابزار توضیح می‌دهد که حذف شده و محتوای ارزشمندش باید به پروفایل اصلی منتقل شود.

## ۲. ورودی
`title`، `overview` (متن کامل)، `skills` (فهرست)، `hourly_rate`، `portfolio` (عنوان + توضیح هر نمونه + نوع آن: کار واقعی برای مشتری، پروژه‌ی شخصی یا تمرینی)، `photo_checklist` (خوداظهاری؛ تصویر در MVP تحلیل نمی‌شود)، `employment_history` و `certifications` (اختیاری)، `target_niche` و `stage` (از پرونده‌ی هنرجو)، `niche_rate_samples` (اختیاری: نرخ چند رقیب که هنرجو خودش دستی دیده است).

| | **جمع** | **۱۰۰** | | | |

سطح‌های ۱ و ۳ حالت‌های میانی‌اند. محاسبه‌ی امتیاز، سقف و داده‌ی ناقص طبق README است.

**قواعد نرخ:** ابزار عدد نرخ را از حافظه پیشنهاد **نمی‌دهد**. بازه‌ی نیچ را از `niche_rate_samples` (که کاربر دستی جمع کرده) یا از تنظیمات مربی می‌گیرد. اگر هیچ‌کدام نیست، معیار ۶ «نامعلوم» است و ابزار توضیح می‌دهد که چطور ۵ تا ۱۰ پروفایل رقیب هم‌سطح را دستی ببیند (بدون اسکرپ). یادآوری: کارمزد آپورک متغیر است (۰ تا ۱۵٪) و پیش از ارسال پروپوزال نمایش داده می‌شود؛ نرخ پروفایل پیش از کسر کارمزد است.

**موارد بدون وزن (چک‌لیست):** سابقه‌ی شغلی، گواهی‌ها، ویدئوی معرفی، سطح زبان، به‌روز بودن availability. ابزار فقط وجود یا نبودشان را گزارش می‌دهد.

## ۵. حکم و خروجی

|---|---|
| ۸۰ تا ۱۰۰ | `strong` — پروفایل آماده است؛ تمرکز روی جاب و پروپوزال |
| ۶۰ تا ۷۹ | `improve` — ۲ تا ۳ اصلاح مشخص |
| کمتر از ۶۰ | `rebuild` — پیش از اپلای بیشتر، پروفایل را بازسازی کن |

خروجی همان ساختار `proposal-review.md` بخش ۶ را دارد (`tool: "profile_review"`). بازنویسی در حد **پیشنهاد تیتر (حداکثر ۳ گزینه)** و **خط‌های اول Overview** است، با جای خالی برای واقعیت‌هایی که در ورودی نیست. Overview کامل نوشته نمی‌شود.

## ۷. تعمیم به پلتفرم‌های دیگر
| معیار آپورک | Fiverr (Gig) | LinkedIn و سایت شخصی (مشتری مستقیم) |
|---|---|---|
| تیتر | عنوان Gig ("I will…") + تگ‌ها | Headline لینکدین؛ عنوان صفحه‌ی اول سایت |
| Overview | توضیح Gig + FAQ | بخش About؛ صفحه‌ی خدمات |
| نمونه‌کار | تصاویر و ویدئوی Gig، portfolio | Featured، case study در سایت |
| نرخ | **پکیج‌ها** (Basic/Standard/Premium) به‌جای نرخ ساعتی؛ معیار جدید «وضوح محدوده‌ی هر پکیج» لازم است | معمولاً در پروفایل نیست؛ در پیشنهاد قیمت ارزیابی می‌شود |
| مهارت‌ها | تگ‌های Gig | Skills |
| عکس | عکس پروفایل + تصویر کاور Gig (وزن بیشتر، چون در نتایج جستجو دیده می‌شود) | عکس + بنر |
| انسجام نیچ | هر Gig یک خدمت؛ انسجام بین Gigها | Headline، About و پست‌ها |

**عمومی:** انسجام نیچ، خط‌های اول درباره‌ی مشکل مشتری، نمونه‌کار با مسئله ← نتیجه، اصالت متن، و خطوط قرمز (ادعای جعلی، هویت واقعی). **مخصوص آپورک:** پروفایل پویا، محدودیت کاراکتر، نرخ ساعتی، و ممنوعیت اطلاعات تماس. سازوکارهای Fiverr در این جدول از دانش عمومی‌اند و پیش از ساخت حالت Fiverr باید با منابع رسمی تأیید شوند.
